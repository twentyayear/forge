Design round · overhaul · 2026-10-21

WORKHART Overhaul

One board for the whole overhaul: what the app is today, the trainer and client loops it must serve, the target screens, three looks within the brand, eight decisions, and the overnight build plan. Picks save to this board's own store and are read back by the build, never re-asked. Four rulings are already taken from this afternoon: one trainer built for many, lean core first, keep the logo and the blue, and authority to commit, migrate and deploy each green unit to alphaecho.io.

1 · What is there today

A strong prototype carrying a real backend

Read from the code and the live droplet, not from memory. The backend is further along than the app that sits on it.

Built and live on alphaecho.io

  • Postgres data of record: users, sessions, workouts, assignments, logs and sets, check-ins, fuel, messages, AI drafts, job runs. Every query scoped by the session's user. 68 server tests green today.
  • Kyle console: roster, per-client dashboard, workout builder, assign to a date, inbox, AI draft queue with approve and auto-send, daily monitor and weekly summary jobs.
  • Client app: check-in, Today, Train with a set grid, Fuel, Progress, Coach thread. Kyle's ElevenLabs voice through one server route with the tuned recipe.
  • Sign-in by password or magic link. Resend sending from mail.alphaecho.io. One trainer, four clients, five logged sessions in the database.

What holds it back

  • One 3,800-line component with a prototype mode and a server mode braided together. Mock data still leaks into server mode (PR chips, the program list, the coach cards).
  • Kyle speaks at scripted moments only. Nothing reacts to what the client just lifted.
  • No programs, no bundles across clients, no email channel, no offers, no achievements, no install on the phone, no payments, no device data.
  • Clients are added with psql. The trainer cannot onboard anyone from the app.

Facts that change two of the goals

Google Fit is ending. Google closed new Fit API sign-ups in May 2024 and the REST API shuts down during 2026 with no server-side replacement. Health Connect (Android) and Apple Health have no web access: both need a native shell on the phone. A web-only app cannot read an Apple Watch.

MyFitnessPal's API is partner-only and has been since 2012. The seamless path is indirect: MFP writes to Apple Health and Health Connect, and a native shell reads those.

Stripe Checkout gives cards, Apple Pay, Google Pay and Link out of the box for monthly or annual plans. PayPal and Venmo are not confirmed for US subscriptions through Stripe; treat them as a later question, not a launch requirement.

2 · The two loops the app must serve

Trainer sets it up. Client lives in it. Kyle's voice ties them.

Trainer loop (Kyle, on a laptop)

1Add a client by email; they get a link.
2Build workouts once; group them into a program.
3Enrol many clients in a program from a start date.
4Roster shows who needs attention first.
5Compose with an AI draft; send in-app and by email.
6Offer a 1:1, a call or a program; requests land in the inbox.

Client loop (on the phone, in the gym)

1Morning check-in sets today's readiness.
2Today shows the session Kyle assigned.
3Log sets against targets; finish each exercise.
4Kyle reacts in his voice to what was just lifted.
5Finish: scorecard, achievements, a summary from Kyle.
6Coach tab: the thread, offers, 30 days of history.

4 · Three looks within the brand

Logo and blue stay. Everything else is up.

Space Grotesk leaves with the old look. Each direction keeps black, white and the one blue; they differ in ground, type and density.

Scoreboard
Barlow Condensed for numbers and titles, Barlow for everything else. Dark ground for the gym, big numerals, blue only where you press or where a number matters.
A · Scoreboard recommendedThe frames above. One system, dark first; the console uses the same tokens at laptop density. Fastest to build because the surfaces already exist in the current app, and the type is already loaded.
Clipboard
IBM Plex Sans Condensed and Plex Sans. Near-white ground, ruled rows, charcoal ink, blue as an underline and a button. Reads like a coach's sheet.
B · ClipboardCalmer, better at a desk, weaker under gym light and with a sweaty thumb. Adds a full token swap and a light-ground pass on every frame.
Split
Scoreboard for the client in the gym, Clipboard for the trainer at the laptop. Same type family, two grounds.
C · SplitEach person gets the ground that suits where they are. Costs two token sets and two contrast tables, and every shared component ships in both.

6 · The overnight build

Night one: the lean core, eleven units

Backend first so every screen is built against a real route. Each unit ships alone with its own gate; a green unit is committed, migrated and deployed to alphaecho.io before the next starts. The Netlify prototype is pinned to a frozen branch before anything moves. The full kit is in docs/comps/overhaul/ (SPEC, EXECUTE).

W.0Fable

Preflight: commit the green U9/U10/U10b work, branch prototype at that commit and point Netlify at it, branch overhaul, baseline gate.

Gate: Netlify builds the prototype from the pinned branch; 68 server tests; build passes.

W.1Sonnet

Trainer tenancy: users.trainer_id, every console query scoped to the signed-in trainer, add-client-by-email with a sign-in link.

Gate: a second trainer in tests sees none of Kyle's clients, workouts, messages or drafts.

W.2Sonnet

Programs and bundles: programs, days, enrolments that write assignments per client from a start date; bulk assign; trainer calendar.

Gate: enrol 3 clients × 4 days = 12 assignments, enrol again = 0 new.

W.3Sonnet

Coach lines: Claude writes Kyle's line after each exercise and at the finish from the sets just logged; the voice recipe is untouched; a fallback line bank when the API fails.

Gate: the line cites the logged numbers; the same request twice returns the cached line; API failure still returns a line.

W.4Sonnet

Achievements: one registry, earned inside the log and check-in transactions, streak math pure and tested, returned with the write and in bootstrap.

Gate: a double log earns once; each rule has a test.

W.5Sonnet

Compose, email and offers: AI drafts per client by intent, broadcast in-app and by email with a send ledger, unread-after-24h email job, offers and requests.

Gate: an email is sent once per message however often the job runs; a client with email off gets none.

W.6Opus

Foundation: tokens in one module, the split of the one big file into app, client, trainer and ui folders, the shell, PWA install (manifest, service worker, iOS instructions), prototype mode removed.

Gate: no colour literal outside the token module (test); installable on a phone; every existing flow still reaches its route.

W.7Sonnet

Client core: Today, Train, the set-end moment, Finish with scorecard and achievement reveal.

Gate: a full session on alphaecho.io as the test client; psql shows the log, the coach lines and the earned row.

W.8Sonnet

Client rest: Coach thread with offers, 30-day History, Fuel restyled, You (profile, device, email preference, sign out), check-in restyled.

Gate: every tab renders real data; history shows only the window.

W.9Sonnet

Trainer core: Roster with needs-you, client page with week strip and assign, Add client.

Gate: Kyle adds a client from the console; the link arrives; the client signs in.

W.10Sonnet

Trainer rest: Build (workouts and programs), enrol, Inbox with drafts, Compose, Offers.

Gate: build a program, enrol two clients, draft and send a message both channels, read it back as the client.

W.11Fable

Round close: specs, loose ends, PRD, CLAUDE.md, memory; the morning report.

Gate: docs match the code; nothing open lives only in chat.

Night two (not in this run)

  • Stripe subscriptions, monthly and annual, Checkout with Apple Pay and Google Pay, the portal, webhook-driven entitlements, the paywall per q3.
  • Web push for installed phones (iOS 16.4+), Kyle's messages and session reminders.
  • Wearables per q4; food per q5; one-time offer checkout per q7.
  • Native shell for Apple Watch and Health Connect, which also brings MyFitnessPal in through Apple Health.

Stop rules

  • A unit that fails its gate twice restarts once on Opus with the same ask. A third failure stops the run with the branch left on its last green commit.
  • A failed deploy read-back reverts on main and redeploys the previous commit.
  • Kyle's voice recipe, the no-speechSynthesis rule, secrets handling and tenant scoping are never relaxed to pass a gate.

In the morning, Sam looks at

  • alphaecho.io on his phone: install it, check in, run the assigned session, hear Kyle after an exercise.
  • The console on the laptop: add a client, build a program, enrol, compose and send.
  • The memory note and docs/comps/overhaul/GATES.md for every gate's real output.
